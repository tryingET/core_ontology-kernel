# ROCS 0.4.6 adoption canary

## Scope and identity

The operator approved an isolated canary and verified branch/PR publication, **not automatic
merge**, direct canonical-main mutation, ontology edits or an ontology release/tag.

- Consumer base: remote `main` at `88f3ec2c0d84d30a84474c455d02dd767418eb78`.
  The local operator checkout at `470ab539` was older; it was not updated or altered.
- Before runtime: ROCS `0.3.0`, source `ecd48bbbf79c3eb8c67726ff238b70320fd4551a`.
- After runtime: ROCS `0.4.6`, exact published source
  `bdb4ac4db29f6f87af884c27e1515acfd131c08d` (`v0.4.6`).
- Causal bundle/pin commit: `95b98f9821402dcacd4dc449bf5291eaf634b8e2`.
- New raw `VENDORED_HASHES.json` SHA-256:
  `1a05dc91dd1546921861851f4f16cf3dc24af00bcf3b962a72283a37a4b68564`.

ROCS was vendored from a clean detached release checkout. `uv --project` selects the interpreter,
not the CLI's source root: the first isolated materialization accidentally selected the controller
cwd at `ac75e95`. Its receipt exposed that mismatch. It was replaced from the actual release cwd,
and the corrected receipt/source identity was checked before all after-gates. No incorrect bundle
was published or installed in the operator checkout.

## Changes and compatibility

The bundle and the common verifier's `TRUSTED_LOCK_DIGEST` move together. Both existing native
wrappers call that common verifier, so both admit the same new receipt. The full gate's separate
`manifest_digest` invocation metadata also moves to the exact new receipt bytes.

The custom full gate and custody implementation are preserved, **not replaced by a shorter generic
bootstrap gate**. This update does not claim adoption of the generic generated wrappers' sealed
anonymous-memfd custody. No verifier adversarial test, ontology source/manifest, hook behavior,
validation threshold, discovery limit or routing assertion was weakened or changed.

Relevant release changes:

| Consumer touchpoint | Classification | Adopted behavior |

  ROCS_CI_PROFILE=main-strict ./scripts/ci/full.sh

plus the full existing cleanup/validate/build/bundle-check/summary/lint/graph/inverses/normalize/

pre-existing verification-OK stdout prefix; JSON checks explicitly account for that exact prefix.

The target upstream release was previously verified on a fresh clean checkout with 353 tests
(AK 6454 evidence 12326). This is upstream proof, separate from the consumer checks above.

workstation `heavy-job` runner, with outputs outside the consumer tree. Both scans exited `0`.
The `surface_delta.py` comparison also exited `0`:

- No introduced vulnerabilities or direct-edge changes.
- One **persisting low** finding: Pygments `2.19.2`, `GHSA-5239-wwwm-4pmq`, fix listed as `2.20.0`.
  Updating that dependency is outside this pin slice; no exploitability claim is made.
- Frozen lock comparison changes only the project entry `rocs-cli: 0.3.0 -> 0.4.6`.

There is no re-calibrated timeout/constant change in this slice. Python runtime-trace autodiscovery
is **unrun/not applicable to these isolated `-I -S -B` launcher processes**; injecting `sitecustomize`
or weakening that isolation would not be equivalent execution. Package identity instead comes
from the verified exact bundle and actual native entrypoint runs, not a claim of runtime-trace
coverage.
