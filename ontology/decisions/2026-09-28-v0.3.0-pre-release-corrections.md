# v0.3.0 pre-release corrections, 2026-09-28

**Decision:** the Holding Owner made these corrections on 2026-09-28 on AK 6167, answering the independent work-product inspection of the v0.3.0 content (AK 6188; findings in AK evidence 11283–11286). They are class C, because until the handover every change to a core concept is class C (ADR-0008 §4).
- Consent: the core layer is held by the Holding Owner. The only other affected holder is the FCOS pilot, because fcos.TestTiers narrows core.VerificationEvent. Test-tier runs check a product against its requirements, so they stay verifications under the narrowed sense.
- Dissent: none.

**Why the identifiers stay:** CORE-INV-002 requires a new identifier for a meaning change to an identifier that consumers have been given in a release. These identifiers entered `main` on 2026-09-27, and no tag carries them; v0.3.0 is their first release. So they are corrected in place, in the open, before the release freezes them. After v0.3.0 the same corrections would need new identifiers and deprecations.

| Identifier | Before | After |
|---|---|---|
| `core.VerificationEvent` | a check of any claim against evidence; the claim is "usually" a requirement or DoD row | a check that a product meets a requirement or a DoD row (combination strategy §4, vocabulary card); schema and replay checks are not verifications |
| `core.ArtefactStatus` | UFO phase | UFO quality with the values approach, preliminary, baseline and update; every artefact holds one of them throughout its life, so the concept is rigid and cannot be a phase |

**Synonyms**

ADR-0008 §1.5 reserves every synonym of a core word, so the synonyms follow the data file:
- **Added:**
  - 'group outcome' on `core.ConsentState`, from the data file;
  - 'NASA concurrence' on `core.ConsentRound`, because a concurrence is a signature, which is an act, so it maps to the round and not to the state.
- **Qualified:**
  - 'Plan', 'Do' and 'Check' become 'PDCA Plan', 'PDCA Do' and 'PDCA Check', like every other mapped source term;
  - the duplicate 'Plan' on `core.MitoSegment.Input` is gone, and the decided 'plan' stays.
- **Removed:** 'Führung segment', 'Leitung segment', 'strategic level', 'tactical level', 'dispositive level', 'operative level', 'verification event', 'Binner MITO-Modell' and 'AK task claim'.

**Consumers**
- **FCOS:** fcos.TestTiers keeps its edge to `core.VerificationEvent` and needs no change.
- **Removed synonyms:** none was ever in a release. A lower layer that used one as its own label should check it with the lookup.
- **ADR-0008 data file:** it still lists 'NASA concurrence' under the word consent and has no PDCA terms. Its holder aligns it; that is class C in governance-kernel.
